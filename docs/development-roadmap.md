# 后续开发计划（里程碑路线图）

> 项目代号：`aluka` ｜ 文档版本：v1.0 ｜ 日期：2026-08-06
> 前置：性能报告（docs/performance-report.md）+ 优化计划（docs/perf-memory-optimize-plan.md）
> 已收官：Node 22 兼容 M1-M5、测试器 T1、打包器 T2、优化 O1/O2。
> 本计划把**全部待办**整合为 5 个里程碑（R1-R5），按依赖排序，附验收标准。

## 1. 背景与目标

性能测试报告与优化计划已产出基线：跨引擎差距 18x–764x（调用主导用例最大）、
**Go 分配+GC 占 25% 热点**、字符串拼接 O(n²) 内存黑洞（rss 3x node）。本计划
设立里程碑把 PF（性能）/ME（内存）任务与遗留工具链项（T1-A8 并发、T2-B5
sourcemap）按依赖与收益排布，形成可逐里程碑交付与验收的路线图。

**总目标**：
- 综合基准相对当前提升 ≥30%（调用主导用例 ≥40%）。
- 峰值 rss 相对当前削减 ≥50%（字符串拼接场景）。
- 工具链补齐：并发测试 + sourcemap。
- 探索项（JIT/数值属性打包/GC 调优）给出结论或落地。

## 2. 里程碑规划总览

| 里程碑 | 主题 | 内容 | 工作量估 | 依赖 | 主线 |
|--------|------|------|---------|------|------|
| **R1** | 字符串与分配 | PF-3 拼接合并 + ME-1 rope 决策 + ME-2 对象批量分配 + ME-5 字符串 intern | ~900-1400 行 | 无 | P1（P0 双目标） |
| **R2** | 调用路径 | PF-1 调用快速路径 + PF-2 小函数内联 + ME-4 函数帧复用 | ~950-1500 行 | R1 | P1（性能核心） |
| **R3** | VM 基础设施 | PF-4 值栈预分配 + PF-6 superinstruction 扩展 + PF-7 二元快速路径 + ME-3 数组增长 | ~700-1350 行 | R2 | P1 |
| **R4** | 工具链收尾 | T1-A8 并发测试执行 + T2-B5 sourcemap | ~700-1100 行 | 无（与 R1-R3 并行） | P2 |
| **R5** | 进阶探索 | PF-5 原生高阶内置 + PF-8 JIT 评估 + ME-6 数值属性打包 + ME-7 GC 调优/--mem + ME-8 payload 压缩 | ~1100-2000 行 | R3 | P2/P3 |

## 3. 里程碑详述

### R1：字符串与分配（P0 双目标：性能 + 内存）

**目标**：消除字符串拼接 O(n²)（最大内存黑洞），对象字面量批量分配，常量去重。

| 任务 | 内容 | 验收点 |
|------|------|--------|
| PF-3 | `s += a + b + c` 编译为单次拼接指令（收集操作数一次 concat） | StrConcat 100K 基准相对 136ms 提升 ≥30% |
| ME-1（决策） | 评估 rope 延迟拼接：先落地 PF-3 后测 rss，若拼接场景 rss 仍 >100MB 则实施 rope | 50K 拼接 rss 200MB → ≤120MB |
| ME-2 | `{a,b,c}` 编译期预知 shape：一次分配 slots + 批量写入 | GCPressure 分配数 -20%；对象 rss 208MB → ≤160MB |
| ME-5 | 常量池字符串去重 + 属性名 intern 表 | 同源码重复字符串字面量共享；模块加载内存下降可测 |

**验收**：StrConcat 性能 -30% 且 rss -40%；`go test ./...` 全绿；node22 15/15。

### R2：调用路径（P0 性能核心）

**目标**：调用主导用例（callOverhead 764x / methodCall 638x / fib30 533x 差距最大）。

| 任务 | 内容 | 验收点 |
|------|------|--------|
| PF-1 | `callClosure`/`invoke` 小函数快速路径（无闭包捕获、参数 ≤4 走专用帧） | CallOverhead 174.7ms → ≤120ms（-30%） |
| PF-2 | 编译期内联纯函数（无 this/闭包/递归/arguments 的短函数体） | 内联后调用帧消除；fib25 差距 110x → ≤80x |
| ME-4 | 帧对象池（嵌套调用复用；async/生成器帧不参与） | fib30 分配数 35.8M → ≤25M（-30%） |

**验收**：MethodCall/CallOverhead -40%；fib30 4.57s → ≤3.5s；回归全绿。

### R3：VM 基础设施（P1）

**目标**：dispatch 与栈/数组热路径削薄，为 R5 打底。

| 任务 | 内容 | 验收点 |
|------|------|--------|
| PF-4 | 编译期统计函数最大栈深，帧进入一次性预留 | ensureStack 2.2% 热点消除；PropAccess/PropSet -10% |
| PF-6 | 追加 superinstruction（PushInt+CallMethod、LoadLocal+SetProp、PushConst+Call） | 指令数减少；MethodCall 再 -10% |
| PF-7 | binAdd/binSub 数字/字符串内联到指令 case | 算术密集基准 -15% |
| ME-3 | ArrayValue 指数增长容量 + 稀疏数组 map 存储 | ArrayPush 1M 内存下降 -30% |

**验收**：综合基准相对 R2 再 -15%；rss 稳定；回归全绿。

### R4：工具链收尾（P2，与 R1-R3 并行）

**目标**：补齐并发测试与 sourcemap（test-bundle-optimize-plan 遗留 P2 项）。

| 任务 | 内容 | 验收点 |
|------|------|--------|
| T1-A8 | `--test-concurrency` 每用例独立 VM/Worker 并行执行 | 多文件测试并发正确（共享状态隔离）；差分不倒退 |
| T2-B5 | 字节码 → 源码行映射（复用 LineStarts），`--sourcemap` 输出 | sourcemap 可被工具还原行号；build conformance 不倒退 |

**验收**：`aluka test --test-concurrency` 实测并行加速；`--sourcemap` 产物行号还原正确。

### R5：进阶探索（P2/P3）

**目标**：探索项落地或记录结论。

| 任务 | 内容 | 验收点 |
|------|------|--------|
| PF-5 | map/filter/reduce/forEach 对原生 ArrayValue 走 Go 实现 | arrayMap 差距 18x → ≤10x |
| PF-8 | 基线 JIT 可行性评估（热点函数 → Go 闭包）；不可行则记录结论 | 结论文档 + 原型（如可行） |
| ME-6 | 全数值槽对象 `[]float64` 打包存储（评估收益后实施） | 数值密集对象内存 -30%（可选） |
| ME-7 | GC 阈值/清扫周期参数化 + `--mem` 峰值报告 | `--mem` 可观测峰值；长跑 rss 稳定 |
| ME-8 | `--compile` payload 常量池压缩 | 产物体积 -20%（字符串共享 + 简单压缩） |

**验收**：arrayMap 差距减半；`--mem`/`--profile` 工具链齐备；探索项结论入库。

## 4. 执行顺序与依赖

```
R1（字符串/分配）→ R2（调用）→ R3（VM 基础）→ R5（探索）
R4（工具链）────────────────────────────── 并行（无依赖）
```

- **R1 是入口**：字符串与对象分配是 pprof 最大非解释器热点，且 ME-1/PF-3
  决策影响 R2 的帧分配设计。
- **R2 依赖 R1**：调用快速路径与帧复用需先确认对象分配基线。
- **R3 依赖 R2**：值栈预分配需函数级栈深统计（R2 内联后指令流更稳定）。
- **R4 无依赖**：可与 R1-R3 任意并行（工具链独立）。
- **R5 依赖 R3**：原生高阶/数值打包在基础热路径稳定后评估。
- 每里程碑独立提交（沿用单 commit/里程碑惯例），验收门槛：`go test ./...`
  全绿 + node22 15/15 + build 19/19 + 基准不倒退。

## 5. 风险与已知限制

| 风险/限制 | 应对 |
|-----------|------|
| rope 改变字符串语义（索引/长度/比较复杂度） | 展平时机精确控制（String()/索引/哈希/比较前）；差分框架验证 |
| 小函数内联破坏 Function.name/arguments/递归 | 仅内联静态判定安全（无 this/闭包/递归/arguments）的函数 |
| 帧复用与 async/生成器挂起冲突 | 复用仅限非挂起帧；asyncRunner/生成器帧不参与池 |
| 并发测试（T1-A8）共享状态 | 每用例独立 VM（复用 runTestFile 模式），跨文件天然隔离 |
| JIT 评估无收益 | 记录结论，聚焦解释器热路径与分配削减 |
| 数值属性打包类型语义（NaN/Infinity） | 仅对已验证全数值槽对象；写入非数值时解包回通用表示 |
